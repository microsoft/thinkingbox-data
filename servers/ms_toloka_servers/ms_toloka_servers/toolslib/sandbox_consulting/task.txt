### Tool Implementation Pattern

#### For Simple Tools (Non-Master)
```python
from typing import Any, Dict, Type
from mcp_core import Tool
from mcp_core.db.database import InMemoryDatabase
from mcp_core.utils.schema_utils import get_schema_without_refs
from pydantic import BaseModel, ConfigDict, Field

class YourToolInput(BaseModel):
    model_config = ConfigDict(
        extra="forbid",
        populate_by_name=True,
        validate_assignment=True,
    )
    param1: str = Field(..., description="...", examples=["..."])

class YourToolOutput(BaseModel):
    model_config = ConfigDict(
        extra="forbid",
        populate_by_name=True,
        validate_assignment=True,
        use_enum_values=True,  # Convert enums to strings
    )
    result: str = Field(..., description="...")

class YourTool(Tool):
    @property
    def name(self) -> str:
        return "tool_name"  # NO namespace prefix

    @property
    def description(self) -> str:
        return "Clear description from spec"

    @property
    def input_schema(self) -> Dict[str, Any]:
        return get_schema_without_refs(YourToolInput)

    @property
    def output_schema(self) -> Dict[str, Any]:
        return get_schema_without_refs(YourToolOutput)

    @property
    def request_model(self) -> Type[BaseModel]:
        return YourToolInput

    @property
    def output_model(self) -> Type[BaseModel]:
        return YourToolOutput

    async def run(self, db: InMemoryDatabase, request: YourToolInput) -> YourToolOutput:
        try:
            # Implementation
            data = db.get_by_id(Model, request.id)
            if not data:
                raise Tool.ExecutionError(f"Not found: {request.id}")

            return YourToolOutput(result="...")

        except Tool.ExecutionError:
            raise
        except Exception as e:
            raise Tool.ExecutionError(f"Failed: {str(e)}")
```

#### For Master Tools (Multiple Actions)
```python
from enum import Enum

# 1. Define action enum
class YourApiAction(str, Enum):
    ACTION1 = "action1"
    ACTION2 = "action2"

class YourApiInput(BaseModel):
    model_config = ConfigDict(
        extra="forbid",
        populate_by_name=True,
        validate_assignment=True,
        use_enum_values=True,
    )

    action: YourApiAction = Field(..., description="Action to perform")
    param1: Optional[str] = Field(None, description="Required for action1")
    # All params are optional, validation happens in methods

class YourApiOutput(BaseModel):
    model_config = ConfigDict(
        extra="forbid",
        populate_by_name=True,
        validate_assignment=True,
    )

    result1: Optional[Dict] = Field(None, description="For action1")
    result2: Optional[bool] = Field(None, description="For action2")

class YourApiTool(Tool):
    @property
    def name(self) -> str:
        return "api"

    @property
    def description(self) -> str:
        return """Multi-action tool description.

        - action='action1': Description. REQUIRES: param1. Returns result1.
        - action='action2': Description. REQUIRES: param2. Returns result2.
        """

    async def run(self, db: InMemoryDatabase, request: YourApiInput) -> YourApiOutput:
        try:
            if request.action == YourApiAction.ACTION1:
                return await self._action1(db, request)
            elif request.action == YourApiAction.ACTION2:
                return await self._action2(db, request)
            else:
                raise Tool.ExecutionError(f"Invalid action: {request.action}")
        except Tool.ExecutionError:
            raise
        except Exception as e:
            raise Tool.ExecutionError(f"Failed: {str(e)}")

    async def _action1(self, db: InMemoryDatabase, request: YourApiInput) -> YourApiOutput:
        if not request.param1:
            raise Tool.ExecutionError("Missing required parameter: param1")
        # Implementation
        return YourApiOutput(result1={...})
```

import pytest
from mcp_core import Tool

## Critical Requirements

### 1. Enums (MANDATORY)
- **All enumerable fields MUST be Enum types**
- Never use Union[Literal["a"], Literal["b"]]
- Enum format: `class YourEnum(str, Enum):`
- Values use UPPERCASE with underscores: `STANDARD = "standard"`

### 2. Type Safety
- **NEVER use Any type anywhere**
- Use Optional[T] for nullable fields
- All fields must have explicit types

### 3. Output Models
- Add `use_enum_values=True` to model_config for output models
- This converts enums to strings in JSON output
- Use Optional[] for fields that may not be present

### 4. Tool Naming
- Tool name property should NOT include namespace
- Example: `name = "search"` not `name = "software_catalog_search"`
- Namespace is added automatically by the server

### 5. ID Generation
- Use deterministic patterns for new IDs
- Format: `PREFIX-2-NNNNNN` for generated IDs
- Format: `PREFIX-1-NNNNNN` for pre-seeded data
- Example:
```python
PREFIX_FOR_NEW_IDS = "APR-2"
count = 0
while True:
    new_id = f"{PREFIX_FOR_NEW_IDS}-{count:06d}"
    if new_id not in existing:
        return new_id
    count += 1
```

### 6. Descriptions Style
- Use natural language, not CAPS for emphasis
- ❌ BAD: "Provide EITHER this OR that"
- ✅ GOOD: "Provide either this or that"

### 7. Handling Null in Optional Fields
- Use `.get()` in tests for Optional fields
- Example: `assert result.get("optional_field") is None`
- Not: `assert result["optional_field"] is None` (KeyError!)

## Common Pitfalls to Avoid

1. ❌ Using `Any` type - use specific types
2. ❌ Missing `get_id()` method in models
3. ❌ Using strings instead of Enums for enumerable fields
4. ❌ Including namespace in tool name property
5. ❌ Forgetting `use_enum_values=True` in output models
6. ❌ Not handling Optional fields properly in tests
7. ❌ Using non-deterministic ID generation (random, timestamps)
8. ❌ Missing `model_config` in Pydantic models
9. ❌ Not re-raising Tool.ExecutionError in try/except
10. ❌ Validating too much - keep guards minimal
